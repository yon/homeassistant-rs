# Plan: T3.2 — WebSocket Handler Refactor

**Date:** 2026-02-08
**Status:** APPROVED
**Task:** Refactor ha-api WebSocket dispatch to reduce god functions and improve maintainability

## Problem

- `handlers.rs` is 2,727 lines — a single file with 55 handler functions
- `dispatch.rs` is 413 lines — a match statement with `conn.validate_id(id)?` repeated on every arm
- Every handler manually constructs `OutgoingMessage::Result(ResultMessage { ... })` boilerplate
- Adding a new command touches 3 files: `types.rs` (enum variant), `dispatch.rs` (match arm), `handlers.rs` (function)

## Approach: Pragmatic Split (Not a Trait Registry)

**Key insight:** In Rust, the enum IS the dispatch registry. A trait-based `HashMap<&str, Box<dyn Handler>>` pattern would add complexity (55 struct definitions, 55 trait impls, boxing overhead) for zero benefit — the match still needs to exist. Python HA uses a registry because Python lacks sum types. Rust has them.

The real value is:
1. **Hoist `validate_id`** — extract from 54 match arms into one pre-dispatch call
2. **Add response helpers** — `send_result`/`send_error` eliminate repeated boilerplate
3. **Split handlers.rs** — into 11 domain modules (~150-480 lines each)

## Changes

### 1. Add `IncomingMessage::id()` method (types.rs)

```rust
impl IncomingMessage {
    pub fn id(&self) -> Option<u64> {
        match self {
            Self::Auth { .. } => None,
            Self::AreaRegistryList { id } | Self::AuthCurrentUser { id } | ... => Some(*id),
        }
    }
}
```

### 2. Add `send_result` / `send_error` helpers (handlers/mod.rs)

```rust
pub(super) async fn send_result(id: u64, data: Value, tx: &Sender<OutgoingMessage>) -> WsResult<()>
pub(super) async fn send_error(id: u64, code: &str, msg: String, tx: &Sender<OutgoingMessage>) -> WsResult<()>
```

### 3. Simplify dispatch.rs

Before (every arm):
```rust
IncomingMessage::GetStates { id } => {
    conn.validate_id(id)?;
    handlers::handle_get_states(conn, id, tx).await
}
```

After (validate once, arms are just calls):
```rust
if let Some(id) = msg.id() { conn.validate_id(id)?; }
msg.dispatch(conn, tx).await
```

The match moves to `IncomingMessage::dispatch()` in a new file or in types.rs, and each arm is a single function call without the validate_id boilerplate.

## Risks

- **File rename (handlers.rs → handlers/)**: Rust handles this transparently — `mod handlers` resolves to either `handlers.rs` or `handlers/mod.rs`.
- **Import changes**: Handlers reference each other (e.g., `entity_entry_to_json` used by entity_registry handlers). Keep shared helpers in `handlers/mod.rs`.
- **Alphabetization**: All `mod` declarations and `use` statements in new files must be alphabetized. Run `lint-alpha.py` after each step.
- **ConfigEntriesFlowProgress branching**: The `flow_id: None` case dispatches to a different handler. Move this into the handler itself.
